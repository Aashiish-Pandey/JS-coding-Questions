
## 1️⃣ Why do we need Async Pub-Sub?

### Problem with synchronous pub-sub

```js
notify(data) {
  this.handlers.forEach(fn => fn(data));
}
```

❌ Issues:

* One slow subscriber blocks others
* Errors in one handler can break the chain
* Not suitable for:

  * API calls
  * setTimeout
  * Promises
  * WebSockets

---

### Real-world example

Imagine:

* Logging service
* Analytics service
* UI update

If analytics takes **2 seconds**, UI should **not wait**.

➡️ Solution: **Async Pub-Sub**

---

## 2️⃣ What is Async Pub-Sub?

> Publisher notifies subscribers **asynchronously**, usually using:

* `Promise`
* `setTimeout`
* `queueMicrotask`
* `async/await`

Subscribers can:

* return promises
* fail independently
* run in parallel

---

## 3️⃣ Basic Async Pub-Sub Implementation

### Simple async observable

```js
class AsyncObservable {
  constructor() {
    this.subscribers = new Set();
  }

  subscribe(fn) {
    this.subscribers.add(fn);
    return () => this.subscribers.delete(fn);
  }

  async notify(data) {
    const tasks = [];

    for (const fn of this.subscribers) {
      tasks.push(Promise.resolve().then(() => fn(data)));
    }

    await Promise.allSettled(tasks);
  }
}
```

---

## 4️⃣ Why `Promise.resolve().then()`?

This forces **async execution**, even for sync functions.

Equivalent to:

```js
queueMicrotask(() => fn(data));
```

---

## 5️⃣ Usage Example

```js
const observable = new AsyncObservable();

observable.subscribe(async (data) => {
  await new Promise(r => setTimeout(r, 1000));
  console.log("Subscriber 1:", data);
});

observable.subscribe((data) => {
  console.log("Subscriber 2:", data);
});

console.log("Before notify");

observable.notify("EVENT");

console.log("After notify");
```

### Output

```txt
Before notify
After notify
Subscriber 2: EVENT
Subscriber 1: EVENT
```

✔ Non-blocking
✔ Parallel execution

---

## 6️⃣ Handling Errors Gracefully

Without protection:

```js
fn(data); // one error breaks everything
```

With async safety:

```js
await Promise.allSettled(tasks);
```

Now:

* One subscriber failing doesn’t affect others
* Errors are captured

## 7️⃣ Topic-based Async Pub-Sub (Advanced)

### Implementation

```js
class EventBus {
  constructor() {
    this.topics = new Map();
  }

  subscribe(topic, fn) {
    if (!this.topics.has(topic)) {
      this.topics.set(topic, new Set());
    }
    this.topics.get(topic).add(fn);

    return () => this.topics.get(topic).delete(fn);
  }

  async publish(topic, data) {
    if (!this.topics.has(topic)) return;

    const tasks = [...this.topics.get(topic)].map(fn =>
      Promise.resolve().then(() => fn(data))
    );

    await Promise.allSettled(tasks);
  }
}
```

---

### Usage

```js
const bus = new EventBus();

bus.subscribe("USER_LOGIN", async (user) => {
  await fetch("/analytics");
  console.log("Analytics sent");
});

bus.subscribe("USER_LOGIN", (user) => {
  console.log("Welcome", user.name);
});

bus.publish("USER_LOGIN", { name: "Aashish" });
```

## 1️⃣0️⃣ Common Interview Follow-ups

### Q: Why not `forEach(async fn => ...)`?

❌ Doesn’t await properly
✔ Use `map + Promise.all`

---

### Q: Microtask vs Macrotask?

* `Promise.then` → microtask (faster)
* `setTimeout` → macrotask

---

## 🔥 Final Simplest Async Version (Recommended)

```js
notify(data) {
  this.subscribers.forEach(fn =>
    Promise.resolve().then(() => fn(data))
  );
}
```
